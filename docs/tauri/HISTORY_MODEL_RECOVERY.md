# 历史会话模型恢复（0.1.2，2026-10-13）

历史会话打开时，Tauri bridge 之前会在没有明确模型选择的情况下直接交给 Go boot；boot 的 CLI 策略故意保留失效的默认模型以报告配置错误。桌面侧已有独立的 `ResolveDesktopNewSessionModel` 策略，但 bridge 没有接入，因此即使有可用的桌面聊天模型，也可能返回泛化的 HTTP 500。

## 修复边界

- 在受配置／凭据锁保护的 runtime snapshot 上选择模型，复用 Wails 的桌面访问过滤与聊天模型恢复规则，并处理已有的 MiMo 兼容引用。
- 隐式恢复历史时，已移除或不再允许访问的已保存 reasoning model 可回到当前桌面选择规则；不把旧模型的 reasoning effort 带到新模型。
- 用户在请求中明确指定模型时仍严格校验，不替换为其他模型。已存在、允许访问的保存选择继续保留。
- 不改写用户的全局或项目默认模型配置，不删除历史，不提交测试模型请求。正常打开后的会话元数据按原有生命周期保存实际选择。
- 没有可用模型时，返回状态绑定的 `400 / model_unavailable`。Rust 仅保留这个已知标记，不把原始错误中的服务商、路径或凭据细节交给前端；界面提示选择可用默认模型后重试。

## 验证

本机安装包与构建产物的 host/sidecar 摘要一致，排除了旧包安装错配。截图所指的 482 条可见消息会话在现场重开未稳定复现；另一个原路径兼容会话稳定触发了 unknown-model/500。在当前配置与该历史的私有副本中，修复前失败，修复后恢复原 5 条可见消息。

- 完整 bridge 回归通过；新增全局／项目失效默认模型、访问限制、显式模型严格性、保存模型移除和配置不被改写的回归。
- Rust response parser 5 项通过，前端恢复提示等 61 项通过；生产前端构建门禁通过。
- 安装包真实 supervisor 在私有副本中验证两条专项历史（5 / 482 条），再验证当前全部 21 条已登记历史：列表来源为 `identity`，逐条打开及 sidecar 重启前后消息数一致。
- 实际 `/Applications` 修复版原生界面打开截图会话及另一条已复现失败的会话，未出现 500。原资料保留，旧 App 留有本机备份。

这些结果不等于已查明所有可能的 HTTP 500；若相同截图会话再次出现异常，应继续定位具体请求和当前配置，而非重置或重导入资料。
