# MiMo 模型切换恢复（0.1.3，2026-10-13）

旧版 MiMo 官方预设仅保存 2.5 模型列表时，设置页会在只读加载中补齐 2.6；项目／运行时加载随后重新合并原始 TOML，却没有再次应用该目录修复。因此设置页可以测试 2.6，会话选择同一个模型却报 `model_unavailable`。

## 修复边界

- 在配置合并后的公共规范化阶段复用现有 MiMo 目录兼容规则，使设置页、项目配置和模型运行时快照看到相同目录。
- 仅补齐未被自定义的旧官方预设；保留自定义模型列表、地址、路由、定价和默认选择。
- 不改写用户 TOML 或 API Key，不重新导入或删除历史。正常模型切换仍按现有生命周期保存会话选择。
- 本次没有发现凭据被切换操作删除的证据：新进程读取原保存密钥的最小连接测试成功。旧 App 的连接测试失败未单独稳定复现；不能将所有网络／服务端失败归因于目录问题。

## 验证

- 配置完整回归和 desktop bridge 完整回归通过；保存密钥切换链路的 race 检查通过。
- 回归覆盖只读设置／项目／运行时目录一致、保存密钥后连续测试、原历史模型切换、失败切换后保留前次选择，以及历史内容不变。
- 0.1.3 app / DMG 构建及前端生产门禁通过，app 深度严格签名验证通过；本地包采用 ad hoc 签名，未 Apple 公证。
- 打包原生宿主在私有资料副本中逐条打开当前全部 21 条登记历史，导航来源为 `identity`；sidecar 重启前后消息数一致。
- `/Applications` 实际 0.1.3 原生界面：打开原项目历史，从 DeepSeek 切换到 MiMo 2.6 Flash 成功；返回模型服务页，直接使用已保存密钥测试，显示「连接成功 · 1035 ms」。未重新输入密钥，未向模型发送历史会话内容。
- 更新保留旧 App，本机安装的 host / sidecar 与构建产物摘要一致。
